# Music Semantic Search Baseline

Этот репозиторий содержит **baseline семантического поиска по музыкальным трекам**.  
Пользователь пишет текстовый запрос (по-русски или по-английски), а система находит треки с описаниями, семантически близкими к запросу.

Архитектура следует классическому паттерну **retrieve & re‑rank**:

1. **Bi-encoder (Sentence Transformers)** строит эмбеддинги описаний треков и запросов и даёт быстрый поиск ближайших описаний по косинусному сходству.
2. **Cross-encoder** пересортировывает top‑N кандидатов, оценивая пары `(запрос, описание)` более точно.

---

## 1. Зачем это нужно

Цель baseline — получить простой, но реалистичный прототип рекомендательной / поисковой системы по музыке:

- вход — **естественно-языковой запрос** 
- выход — список треков с артистами, названиями и описаниями, отсортированный по смысловой близости к запросу.

---

## 2. Данные

### Источник

Корпус описаний собирается через **Last.fm API**:

- `track.getInfo` — описания треков (`track.wiki.summary`) и базовая мета-информация;
- `tag.getTopTracks` — треки по жанровым / стилистическим тегам для разнообразного каталога.

Мы:

1. Берём список тегов (жанры, стили: `rock`, `pop`, `hip-hop`, `indie`, `jazz`, `metal`, `ambient`, `k-pop`, …).[web:523]
2. Для каждого тега забираем топ треков.
3. Дедуплицируем по `(artist, name)`.
4. Через `track.getInfo` подтягиваем `wiki.summary` и дропаём треки без описания.[web:478]

В итоге получается датафрейм вида:

| Колонка      | Описание                                      |
|--------------|-----------------------------------------------|
| `artist`     | Имя артиста                                  |
| `name`       | Название трека                               |
| `tag`        | Тег, через который трек попал в каталог      |
| `description`| Текстовое описание (summary из Last.fm)      |

Треки без `description` удаляются перед построением эмбеддингов, поскольку для них нет текстового сигнала для семантического поиска.

## 3. Архитектура baseline

### 3.1. Общая схема

Пайплайн разбит на три этапа:
1. **Indexing (fit)**  
   - Модель Sentence Transformers кодирует все `description` в векторы фиксированной размерности.  
   - Эмбеддинги нормализуются по L2‑норме, чтобы скалярное произведение было косинусным сходством.[web:648][web:655]

2. **Retrieval (retrieve)**  
   - Пользовательский запрос кодируется той же моделью.  
   - Вектор запроса сравнивается с эмбеддингами всех описаний, считая косинусное сходство.  
   - Выбирается top‑N (например, 50) кандидатов с максимальным сходством.[web:643][web:651]

3. **Re‑ranking (rerank, опционально)**  
   - Для каждого кандидата формируется пара `(query_text, description)`.  
   - Cross-encoder (например, `ms-marco-MiniLM-L6-v2`) выдаёт более точный `rerank_score` для пары.[web:620][web:622]  
   - Кандидаты пересортировываются по `rerank_score`, и берутся top‑k (например, 10).[web:706][web:708]

### 3.2. Модели

**Bi-encoder (retrieval)**  
Рекомендуемая модель:

- `sentence-transformers/paraphrase-multilingual-mpnet-base-v2` — мультиязычный encoder, который одновременно поддерживает английские описания и русские запросы.[web:652][web:656]

Это позволяет отказаться от внешних переводчиков и делать поиск напрямую:  
русский запрос → вектор → поиск по английским описаниям.

**Cross-encoder (re‑rank)**

- `cross-encoder/ms-marco-MiniLM-L6-v2` — компактный re-ranker, обученный на задаче ранжирования MS MARCO.[web:622]

Он получает на вход пару текстов и выдаёт скалярный score релевантности. Используем его только на top‑30–50 кандидатов, чтобы не платить большую цену за inference на всём каталоге.[web:620][web:623]


## 4. Как запустить

### 4.1. Установка зависимостей

```bash
pip install sentence-transformers pandas numpy
```

### 4.2. Подготовка данных

Ожидается датафрейм `tracks` со столбцами:

- `artist`
- `name`
- `description`

Пример (упрощённо):

```python
import pandas as pd

tracks = pd.read_parquet("/data/processed/data_fm.parquet")
# или:
# tracks = pd.read_csv("/data/processed/data_fm.csv")
```

Убедись, что строки без `description` удалены заранее.

### 4.3. Инициализация baseline

```python
baseline = MusicSearchBaseline(tracks)
baseline.fit()
```

Можно сохранить эмбеддинги, чтобы не считать их каждый раз:

```python
baseline.save_embeddings("/data/processed/data_fm_embeddings.npy")
# ...
baseline.load_embeddings("/data/processed/data_fm_embeddings.npy")
```

## 6. Примеры поиска

```python
baseline.search(
    query="мрачный атмосферный постпанк с гитарой",
    top_n=50,
    final_k=10,
    use_rerank=True
)
```
